# Deploying the Lodgiva API to Render

The blueprint is `render.yaml` at the repository root. It declares the service
and every variable it needs; it contains no secrets.

Read §1 before starting. The API **refuses to boot** in production until
storage is genuinely configured, and that is a Cloudflare R2 bucket, not a
setting you can skip.

---

## 1. What you must have first

| Requirement | Why it is not optional |
| --- | --- |
| **Neon connection strings** (pooled + direct) | Already in use locally. Prisma needs the direct URL for migrations and the pooled one at runtime. |
| **A Cloudflare R2 bucket pair** (public + private) | `assertSafeProductionEnvironment()` rejects any other adapter in production. Render's disk is ephemeral: the local filesystem adapter would lose every guest ID scan and invoice PDF on each redeploy. |
| **A paid Render instance** (Starter or above) | `preDeployCommand` runs migrations before traffic shifts. On the free tier, move that command into `buildCommand` — and note free services sleep, so the first request after idle takes ~30s. |

Verify the guard yourself before paying for anything:

```bash
node -e "require('./apps/api/dist/common/runtime-config.js').assertSafeProductionEnvironment({NODE_ENV:'production'})"
```

It prints the complete list of what is missing.

## 2. Deploy

1. Render dashboard → **New → Blueprint** → connect `Obiajulu-gif/lodgiva`.
2. Render reads `render.yaml` and prompts for each `sync: false` variable.
   Fill them in from §3.
3. Apply. The first build runs `pnpm install`, generates the Prisma client,
   compiles the API, runs `prisma migrate deploy`, then starts.
4. Watch the health check at `/api/v1/health/ready` — it runs a real query, so
   a service that cannot reach Neon never receives traffic.

## 3. Values to supply

```bash
# 32 bytes, base64 — the guard checks the decoded length exactly.
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | Neon **pooled** string (`-pooler` host) |
| `DIRECT_URL` | Neon **direct** string (no `-pooler`) |
| `MFA_ENCRYPTION_KEY` | Output of the command above |
| `R2_ENDPOINT` | `https://<account>.r2.cloudflarestorage.com` |
| `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` | R2 API token pair |
| `R2_PUBLIC_BUCKET` / `R2_PRIVATE_BUCKET` | e.g. `lodgiva-public`, `lodgiva-private` |
| `R2_PUBLIC_BASE_URL` | Public bucket's HTTPS URL |
| `STORAGE_BASE_URL` | The API's own HTTPS origin, e.g. `https://lodgiva-api.onrender.com` |
| `PAYSTACK_SECRET_KEY` / `PAYSTACK_WEBHOOK_SECRET` | From the Paystack dashboard |

`JWT_SECRET` and `STORAGE_SIGNING_KEY` are generated by Render — leave them.

**Never paste these into `render.yaml`.** It is committed and readable in every
pull request.

## 4. Point the front end at it

The Vercel app proxies `/api/v1/*` through a Next rewrite, so the browser only
ever talks to `lodgiva.vercel.app`. That is what keeps the refresh cookie
first-party — do not replace the rewrite with a direct cross-origin call, or
`SameSite=strict` will drop the cookie and every session will die on refresh.

```bash
vercel env add LODGIVA_API_ORIGIN production   # https://lodgiva-api.onrender.com
```

```bash
cd apps/marketing-web && npx vercel --prod --yes
```

Then confirm the proxy actually reaches the API:

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://lodgiva.vercel.app/api/v1/health/live
```

`200` means done. `404` with `DNS_HOSTNAME_RESOLVED_PRIVATE` means
`LODGIVA_API_ORIGIN` is still unset and the rewrite is falling back to
`localhost:4000`.

## 5. After the first deploy

- **Seed or onboard.** The Neon database has never been seeded, so
  `owner@grandpalm.demo` does not exist. Either run `pnpm db:seed` (upsert-only,
  no deletes) or just use `/signup` — it creates a real tenant, which is the
  path a customer takes anyway.
- **Register webhooks** with Paystack at
  `https://lodgiva-api.onrender.com/api/v1/gateway/webhooks/paystack`. Do not
  put a bot challenge in front of it: providers are not browsers, and the HMAC
  signature is what makes the callback trustworthy.
- **Block `/api/v1/metrics`** at the edge. It is public by design for a
  scraper; see `docs/operations.md` §2.
- **The outbox worker is not in this blueprint.** `apps/worker` drains queued
  push notifications and outbound events. Until it runs somewhere, those rows
  accumulate unprocessed. Add it as a second Render service (`type: worker`,
  `startCommand: pnpm --filter @lodgiva/worker run start`) when you need it.
